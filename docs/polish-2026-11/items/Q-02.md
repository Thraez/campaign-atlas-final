# Q-02 The handoff lands on the map

Branch `polish-q02-handoff-lands-on-map` (from `main` e609ab8d). 2026-11-25. v2 shared canvas only.

**The rule:** when a zoom in settles on a map (entering it by a handoff included) and the map is
left alone for 150 ms, the camera slides the shortest way that leaves no sea on a side the map
could fill, and puts the whole map on screen along a side where it is smaller than the screen.

## Causes

1. **Sea landing.** The handoff itself lands right: the anchored (P-04) or centre entry shows the
   whole entered map. But a wheel zooms about the pointer, and an entry at a frame's edge leaves
   the pointer on the new map's edge or over its sea. Every further notch then grew the map away
   from the pointer into a corner (from the ocean at the playtest spot: Oskmark ended at 36-38% of
   the screen, the rest sea). Nothing in a map view kept the map on screen. Not two handoffs, not
   clamping, not the camera carry-over.
2. **Wrong-scale frame and route mid-glide.** Leaflet's SVG renderer clips paths to the viewport
   (plus 10% padding) when a move ends. During `flyTo`/`flyToBounds` (crumb, Reset, fit) it only
   scales that clipped picture with CSS and re-clips at `moveend`. Gliding out from a deep zoom,
   the clip edge showed as a small dashed rectangle (the child frame cut to the old viewport) and
   routes stopped short at it, at the old scale, until the glide landed. Pins, labels and map
   pictures were right every frame; it was never old/new coordinates mixing.

## What changed

All in `src/atlas/canvas/`; nothing outside the canvas, no CSS.

- `mapSettle.ts` (new, pure): `settledCentre` (per axis, clamp the centre to
  `[min(half, span - half), max(half, span - half)]`; null under 1 screen px) and `insidePolygon`.
- `MapZoomSettle.tsx` (new): in a map view, a user zoom in that settles without a handoff
  (`ZoomHandoff` calls `settle.zoomedIn`) and a handoff into a map below (`AtlasCanvas.reportView`
  marks `settle.entered`) arm one `SETTLE_IDLE_MS` timer, Q-01's settle pattern: zoomstart, drag,
  touch and pointer press disarm it, a wheel restarts it. Then `panTo` (`GLIDE_SECONDS`; a jump
  in calm mode), clearing `armed` so it never hands off. It never slides while the pointer is
  over a child's frame (P-04's entry at a frame by a map's edge). Zoom out, fits, glides, drags
  and the ocean (Q-01's `OceanZoomLimit`) are untouched.
- `RedrawVectorsWhileMoving.tsx` (new): on each `zoom` event outside Leaflet's own zoom
  animation (glides, pinch), every `L.Renderer` runs `_reset()` (re-project and re-clip). Uses a
  Leaflet 1.9 private method; Leaflet's CSS zoom animation (wheel, buttons) is left alone.
- `ZoomHandoff.tsx`: `finish` split into `handOff`, which returns whether it handed off.
- `AtlasCanvas.tsx`: wires both, mounted after `CanvasCamera`.

Tests: `src/test/canvas/map-zoom-settle.test.tsx` (14). Without the two components, 5 fail (edge
zoom, calm jump, handoff into the cove's corner, pointer off frame, renderer redraw).

### Review fixes

- The pointer's last position lives in a ref with its own `[map]` effect, so it outlives a view
  change: right after a one-notch handoff (no pointermove since), a grandchild's frame under the
  still pointer is not slid away, and the next notch enters it.
- `entered` is `{ key, at }` and set for any map below the current view (a pinch, keyboard or
  double-click zoom can pass several enter zooms; `maxSteps` is 1 only for wheel). It is null on a
  hand-back up, used up by the view it names, and ignored and dropped after
  `ENTERED_WINDOW_MS` (1000), so a handoff the caller ignored can't make a later calm-mode jump
  to that map slide.
- Arrow-key keydown disarms the settle (Leaflet's keyboard pan).
- `RedrawVectorsWhileMoving`: `typeof _reset === "function"` guard; counts `zoom` events outside
  Leaflet's zoom animation since zoomstart and redraws from the second on, so a calm-mode jump
  and the end of a wheel/button CSS zoom (one `zoom` each, redrawn by Leaflet at moveend) are
  skipped.
- Tests (23): the fake's `panTo` and `flyTo` are interruptible (as in `one-ocean-view.test.tsx`);
  new: user input during a running slide, a glide starting while armed, a calm pinch with no
  zoomend, a glide stopped by a drag, a handoff with the pointer over a grandchild (a third map
  "pool" in the cove), a keyboard zoom entering two levels, an arrow key, a stale `entered`, the
  redraw skips and a renderer without `_reset`. The grandchild test fails with the pointer reset per
  view.

Per-frame cost of the redraw (main atlas, crumb glide Oskmark cz 2.5 to Quessaly, Chromium
375x812, CPU throttled 4x, 6 runs each; 4 overlay paths, the most of the test atlases):

| | rAF interval, first 500 ms (median / p90 / max) | main thread over 600 ms: task / script (mean) |

| Without the redraw | 16.7 / 16.7 / 33.3 ms (one 33 ms frame in 6 runs) | 140 / 46 ms |
| With the redraw | 16.7 / 16.7 / 33.3 ms (two 33 ms frames in 6 runs) | 144 / 53 ms |

About 7 ms more script per glide (24 redrawn frames), about 0.3 ms a frame at 4x; no frame
budget lost. The with-build redraws every frame: 24 distinct path states in 43 frames at 1440x900.

Browser recheck after the fixes (1440x900): from Quessaly cz 1.9, one notch with the pointer
still at (440,140) or (460,160) lands in Oskmark over Brindlecross's frame; the camera stays put
for 1.5 s, and further notches enter Brindlecross. Pointers off a frame after the same handoff
still slide onto the map. The original sea landing (ocean, pointer (287,480), 10 notches) ends at
100%, as before.
