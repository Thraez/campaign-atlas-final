# Q-04: Small finish

Five small fixes to the map's chrome. Checked on the `atlas:publish:next` build served by
`atlas:serve:next` (Lantern Road, Oskmark), in a fresh Chromium profile, at 1440x900 and 375x812.
Shots: `docs/polish-2026-11/shots/q04-*.png`.

## 1. Sea seams

- **Cause:** each of the three wave layers was a tiled background (80, 120 and 60 px wide) holding a
  slanted `repeating-linear-gradient`, slid with `background-position`. A slanted stripe does not
  line up across a vertical tile edge, so every tile edge showed a seam. All three layers met every
  240 px, which made the visible seams there. On a phone the same edges read as light bands.
- **Change (`src/atlas/ocean/OceanBackground.tsx`):** each layer is now one untiled gradient. It is
  wider than the sea by one horizontal stripe repeat (`period / sin(angle)`: 122.97, 144.15 and
  107.47 px) and starts that far to the left. It moves by `transform: translateX(0 → repeat)`, which
  lands on an identical picture, so the loop has no jump. Stripe angle, spacing, crest colour and
  opacity are unchanged, and the durations are scaled so the drift speed in px/s is the same.
  Moving by transform is done by the compositor with no repaint, so the sea is cheaper to draw than
  the old `background-position` slide. The reduced-motion and calm (`data-calm`) rules still set
  `animation: none`.
- **Checked:** a column-gradient seam detector (scratch script) ran on 3 frames each at 1440 and
  375. Before, it found seams every 80 px on desktop and at 92/172/252/332 px on the phone. After,
  it found none. A side-by-side crop shows the same stripes. The existing canvas test (animation
  `none` under reduced motion) still passes.
- **Not checked:** frame timing (no profiler run); Safari and Firefox.

## 2. One focus ring

- **Cause:** shadcn `Button`s use `ring-2 ring-ring ring-offset-2`. The crumbs had no focus style.
  Reset used the browser default. The Leaflet zoom buttons had a 2px inset outline.
- **Change:** `src/index.css` adds a new class, `.atlas-focus-ring:focus-visible`, and the
  `.leaflet-control-zoom a:focus-visible` rule. Both use the box-shadow that `ring-2 ring-offset-2`
  makes (`0 0 0 2px background, 0 0 0 4px ring`) with no outline. Zoom links get `z-index: 1` so the
  ring is not covered by the button next to them. The crumbs (`MapBreadcrumb.tsx`), including
  "Earlier levels", and Reset (`AtlasViewer.tsx`) use the class. The crumb list gets `p-1 -m-1` so
  the ring is not clipped, with the same footprint.
- **Checked:** computed styles in the browser for a crumb, a zoom button and Reset are identical:
  `rgb(14,17,22) 0 0 0 2px, rgb(223,163,73) 0 0 0 4px`, outline none. Screenshots of each focused.
- **Not checked:** v1 maps separately. The controls are the same components and CSS in v1, so the
  change applies there too, but no v1 map was opened in the browser.

## 3. Reset icon

- **Change:** lucide `Maximize2` (which reads as fullscreen) is replaced by lucide `Map` in
  `AtlasViewer.tsx`. The icon is `aria-hidden`. `aria-label="Reset map view"` and the tooltip are
  unchanged.
- **Checked:** a smoke test covers the name, the tooltip, the hidden icon and that it is `lucide-map`.
  Seen in the browser.

## 4. Places counter

- **Change (`WanderControl.tsx`):** the meter row gets a quiet pill: `rounded-full bg-background/85
  px-1.5` and a `ring-1 ring-inset ring-border`. The ring is drawn inside the box, so there is no
  layout shift.
- **Checked:** the Wander block measured the same before and after (desktop 12,828 101x60; phone
  12,738 101x62). Seen in the browser over the sea and over land.

## 5. Sound invite

- **Cause / scope:** the welcome invite stayed until it was dismissed. Its lifetime is local UI state
  in `SoundControl` and is not tied to sound state, so the sound logic is untouched.
- **Change (`SoundControl.tsx`):** after `INVITE_VISIBLE_MS` (12 s) the text and the ✕ fade out over
  600 ms. The invite then folds to a 40x40 speaker button ("Turn on sound", same tooltip text) that
  calls the same `enableSound`. With reduced motion or calm mode it folds at once, with no fade.
  Pointer over the invite or focus inside it holds it open; a fade that is in progress comes back.
  Dismiss still removes it entirely. The resume invite ("Tap to resume sound") is unchanged.
- **Overlap:** the boxes did not intersect (there was a 10 px gap). However, the invite's x range
  ran about 6 px over the scale bar, and its `shadow-md` reaches about 9 px below it. The desktop
  notice dock's `bottom` goes from 4rem to 4.5rem, which gives an 18 px gap. The phone is unchanged.
- **Checked:** unit tests (fake timers) cover: full, then fading, then folded; the folded button
  turns sound on and folding never does; calm mode folds straight away; hover and focus hold it
  open; dismiss removes it. In the browser: full at 3 s, the speaker button at 14 s, no sound
  preference saved, and folded at 12.4 s under reduced motion.
- **Not checked:** actually hearing sound after a click on the folded button (it is the same handler
  as the full invite's).

- The folded speaker button is new UI. It is shown only after the invite folds.
