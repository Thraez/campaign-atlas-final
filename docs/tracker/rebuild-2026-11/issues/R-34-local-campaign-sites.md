# R-34 Serve the test world's campaign sites locally, with a picker

Status: ready-for-agent
Blocked by: R-30
Size: S
Branch: `rebuild-r34-local-campaign-sites`
Model: Opus (`scripts/`, `vite.config.ts`)
Needs: the adversarial player-safety review: the picker lists every campaign, so it must never land
in a campaign's site

`atlas:publish:next` builds each test-world campaign into `dist-campaigns/<id>/`
(`scripts/atlas/publishPlan.ts`), but nothing serves them: `.claude/launch.json`'s
`atlas-pages-preview` serves `dist/` (v1). Phase 3's check (R-36) needs Ocean > continent > city >
back on each campaign's real site build. ux-flows p6 keeps a campaign picker (P6) for the test site
and the preview only; hosted players arrive by their own campaign's link (ADR-0007, phase H).

## Acceptance criteria

- `npm run atlas:serve:next` serves every built campaign site from `dist-campaigns/` on one local
  port: each at `/<id>/` (built with that base; `ATLAS_BASE` or the per-campaign build's `base`),
  and at `/` a picker page (P6: each campaign's name and a link; "Test site only" note). It
  refuses, naming the command, if `dist-campaigns/` is missing or stale against the store.
- The picker page is generated by the serve command (or into a gitignored dir outside
  `dist-campaigns/<id>/`) and is never written into any campaign's site dir or store; the
  isolation scan's site file list check (`check-campaign-isolation`, R-19) still passes on every
  site, and a test pins that no campaign site dir contains the picker or another campaign's name.
- The per-campaign site build still passes `atlas:scan --config atlas.next.config.json` with the
  changed base (if the base changes), and v1's `dist/` build and `publish-atlas.yml` are unchanged.
- `.claude/launch.json` gains `atlas-campaigns-preview` running it, so the preview pane and the
  playtester can open it.
- `README.md` / `COMMANDS.md` list the command.
- `npm run gate` passes.

## Provisional calls (noted in State.md)

- One port with a path per campaign, rather than one port per campaign, so the picker can link to
  each; the hosted sites (H-01) are one hostname each and don't use this path layout.
- The picker doesn't remember the choice in the browser (ux-flows p6.2): on a local test site it
  saves nothing worth the code.

## Touches

`scripts/atlas/` (a serve script), `package.json`, `vite.config.ts` or `publishPlan.ts` (base per
campaign, if needed), `.claude/launch.json`, docs.

## Out of scope

Hosting (H-01..H-04), the editor's preview as a campaign (E11, phase 6).
